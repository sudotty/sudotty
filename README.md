# Hi, I'm sudotty

Full-stack / backend engineer focused on **production-grade AI agent systems**.

I started software development in 2012 and have worked across financial systems, tax systems, backend services, data processing, web applications, mobile apps, and internal business tools.

My current work is centered on one practical question:

> How do we make AI agents reliable enough for real work?

I am building a focused portfolio around the production problems that appear after the first demo works:

- RAG reliability and retrieval evaluation
- MCP tool integration and tool safety
- Human-in-the-loop workflow agents
- Issue-to-PR coding agents
- Agent evaluation, tracing, and failure debugging
- Deployment, audit logs, permissions, and cost control

I care less about impressive chatbot demos and more about systems that can survive contact with users, data, tools, policies, and failure.

## Featured AI Agent Projects

### [Production Agent Starter Kit](https://github.com/sudotty/production-agent-starter-kit)
A production-style starter kit for building, running, evaluating, and governing AI agents with RAG, MCP tools, human approval, tracing, and regression tests.

### [RAG Reliability Lab](https://github.com/sudotty/rag-reliability-lab)
A RAG evaluation lab with hybrid retrieval, reranking, citation validation, hard-case analysis, and regression evaluation.

### [MCP Tool Safety Gateway](https://github.com/sudotty/mcp-tool-safety-gateway)
A secure tool gateway for AI agents with MCP connectors, JSON Schema validation, permission policies, dry-run execution, idempotency keys, and audit logs.

### [Agent Eval & Debug Suite](https://github.com/sudotty/agent-eval-debug-suite)
An evaluation and debugging suite for comparing agent versions, diagnosing failures, tracking cost per success, and blocking regressions before release.

### [Human-in-the-loop Workflow Agent](https://github.com/sudotty/hitl-workflow-agent)
A workflow agent for invoice reconciliation and payment approval, combining structured extraction, policy checks, risk scoring, tool dry-runs, approval gates, and audit trails.

### [Issue-to-PR Coding Agent](https://github.com/sudotty/issue-to-pr-coding-agent)
A coding agent that turns small GitHub issues into tested draft PRs with repository context, minimal patches, test feedback, repair loops, and PR summaries.

## Working Principles

- Build the smallest useful system first.
- Prefer boring reliability over decorative complexity.
- Make the invisible visible: traces, failures, costs, and decisions.
- Keep a human in the loop when actions are risky.
- Write clear docs because remote work is mostly asynchronous trust.
- Measure quality before calling a system production-ready.

I like engineering that is precise without becoming mechanical. Rilke is a quiet reminder for me: real work requires attention, patience, and the courage to keep becoming more exact.

> The shortest answer is doing.
